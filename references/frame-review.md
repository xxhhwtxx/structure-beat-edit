# 逐帧检查与交付

## 证据范围

“完整解码成功”“生成了全部帧截图”“实际查看全部帧”“放大检查关键边缘”是四件事，报告时分开。脚本不能代替看图，也不能用平均误差证明遮罩没有漏色。

用户要求全部逐帧时：

1. 完整解码最终导出的文件，检查实际帧数、PTS 与音轨。
2. 生成覆盖每帧、带帧号和时间的连续对照图，按顺序实际查看，不能漏最后一页。
3. 对静态重复状态检查保持稳定性；每种独立状态留原尺寸截图，边缘问题打开 100% 原尺寸或同坐标裁切。
4. 动画不能只检查首尾。转动、缩放、擦除、跟踪与遮挡交界要覆盖中间帧，发现变化后缩小到相邻帧。
5. 修改后重新从导出文件取证，旧截图不证明新版。

短静帧卡点片可以按状态分组细查；连续实拍的每帧本来就不同，不能把正常运动当异常闪动。

## 常见检查项

- 语义：校名旁的装饰、门洞、花心、细枝、倒影、低处窗户、广场标线是否被误选。
- 边界：灰边、光晕、锯齿、孤立色点、穿孔、屋顶上色缺口、遮挡关系。
- 时间：计划内事件开始/落拍/结束是否准确；有无残留一帧、黑帧、切镜错一帧。
- 运动：对象与 alpha 同步；变换锚点、透视、裁切边界与跟踪稳定。
- 音频：起点、结尾、原声关系、静音或截断；要求音轨原样保留时比较音轨内容，不比较整个 MP4 文件哈希。
- 技术：尺寸、SAR、帧率、色彩管理、音轨与完整解码。明确源像素不足或已剪白的高光，不能宣称修复了不存在的细节。

## 统计的用途与限度

`media_audit.py` 输出逐帧平均差、亮度、色彩比例与暗帧候选；有计划时检查事件位置、总帧数和指定静止段。阈值随工作分辨率和素材变化，默认值不是普遍标准。

计划里的 `holds` 只声明本来应静止的区间。不能为摇移、人物运动或连续动画设置静止保持。事件帧变化小不必然失败，例如低饱和小物件；脚本只列候选，需人工确认。

如果要比较渲染预期，双方应使用相同色彩矩阵与范围转换，避免 OpenCV 和 FFmpeg 解码差异造成假报。对比全图后再对细节 ROI 对比；压缩后不要求逐字节相同。

修复已知问题后，做与本轮修改相关的复核；全部通过则交付，不无理由反复重新设计。
