# 参考与节奏

## 先建立事实

取得视频参数与整片概览。将变化分成：源镜头切换、相机/人物运动、局部颜色变化、抠图/布局变化、整体调色/反相、叠加插片、声音动作。先记录观察，未知处标“待核对”，不要凭标题推测内容。

保存紧凑表：时间/帧、画面对象、可观察动作、累计/替换/抽离语义、节奏角色、下镜连接。整体概览可以低密度；变化处用 3–7 个时点缩小范围，再看相邻帧。镜头边界只在画面证据充分后确认。

## 时间坐标

- 项目事件采用输出时间线帧，0 起算，区间 `[start, end)`。
- CFR 映射：`time = frame / fps`。23.976、29.97 用有理数，不当成整数。
- VFR 用 PTS；源 PTS、素材裁切起点、变速、输出帧必须有明确映射。
- UI 显示的 1 起算帧号与内部 0 起算分开。
- 不用视频帧数推音频时长。HE-AAC/SBR 的编码包可能对应不同的有效采样数。

## 音乐与事件

1. 找乐句和明显段落变化，再找主拍。
2. 在主拍之间安排符合结构数量的细分拍；停顿和留白也是设计。
3. 将“动作开始”“达到关键位置”“完全揭示”分别标记。击打感通常来自关键位置落拍，不能只把长动作起点放到重音。
4. 回听确认，或明确只做了波形/频谱候选分析。听觉证据不可用时，不宣称已经确认听感。
5. 瞬态检测会把高帽、语音辅音和噪声也当峰。脚本不直接给出可靠 BPM，不自动填写最终拍点。

`media_audit.py --audio-onsets` 使用短时频谱正向变化找候选，并记录实际解码后的音频长度。结果用于缩小审听范围，不是完成的节拍网格。

## 素材匹配

先列出每镜可操作的结构以及相机运动。重复结构越清楚，越适合有方向的累计动作。没有重复结构的镜头可以担当完整画面、留白或过渡，不必强塞相同效果。

参考里存在某效果，只代表可以选用。时间、窗口数量、颜色、亮度、镜头长度随新素材重新决定；不把这次参考的 14 秒和 30 fps 固定成要求。
